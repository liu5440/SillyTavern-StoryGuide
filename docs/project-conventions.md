# 项目与代码规范

版本：0.1｜日期：2026-11-13｜适用于本仓库全部人工与 AI 贡献。

## 1. 需求是开发边界

- 实现必须对应 [需求文档](requirements.md) 的 FR 编号及验收条目。
- 未定义的产品能力不得顺手加入；常规局部技术细节可自行决定并记录。
- 影响产品范围、数据格式、宿主集成或持久化的变更，先更新设计与契约，再编码。
- 当前已进入首版实现；技术决策和已验证范围分别见宿主契约与验证记录，不把未验证能力写成事实。
- 禁止创建独立聊天产品、登录系统或额外服务端替代酒馆扩展。

## 2. 技术基线与决策

建议采用 TypeScript 严格模式和 ES Modules；构建产物必须能由酒馆原生扩展加载。界面框架、图组件及构建工具在集成验证阶段通过决策记录确定，不能因为其他项目使用 Vue 就自动照搬全套管理后台。

新增依赖须说明用途、替代方案、体积、许可证及是否存在运行时外部请求。优先复用宿主公开能力，但业务层不能绑定宿主内部路径。

没有后端时不设想 `/api/v1`、账户登录或刷新 Token。禁止从参考技能复制与本项目无关的认证规范。

## 3. 建议目录与职责

以下为后续目录约定，不表示当前已有这些文件：

```text
manifest.json          酒馆扩展清单
src/entry.ts           初始化、注册入口、清理
src/host/              酒馆 API、事件、模型连接及存储适配
src/domain/            故事、图、条件、来源、进度等纯逻辑与类型
src/application/       解析、生成、采用、导入导出等用例
src/ai/                提示模板、批次编排、结果校验与修复
src/storage/           持久化、版本、迁移与配额处理
src/ui/                面板、图、表单、交互状态和样式
tests/                 领域、契约及必要流程测试
docs/                  需求、规范、契约、决策、验证记录
```

- UI 不直接请求模型、读写宿主内部状态或实现图校验。
- domain 不依赖 DOM、宿主全局对象、网络或存储。
- 只在 host 层访问 `SillyTavern.getContext()` 等宿主入口。
- 模块围绕职责拆分；不得把所有业务集中在 index 文件，也不为简单代码过度分层。
- 宿主能力不可用时显式报告不支持；禁止抓取随机 DOM 文本冒充稳定 API。

## 4. 代码可读性

- TypeScript 开启 strict；禁止无解释的 any、ts-ignore 和非空断言。
- 跨模块边界接收 unknown 后验证，不能靠类型断言假装输入合法。
- 函数、变量使用清晰英文名，用户文案及业务注释用中文；稳定实体使用不可变 ID，名称可编辑。
- 复杂业务、状态迁移、来源判定与副作用边界使用中文 `/** ... */` 说明目的和约束，不逐句翻译代码。
- 优先小函数和纯函数；避免复制条件规则、来源规则及剧透规则。
- 不遗留 console.log 调试数据；日志按级别输出任务 ID 和脱敏错误，禁止打印原始角色卡、完整聊天和密钥。

## 5. 宿主契约

实现集成前建立 `docs/host-contract.md`，记录实际验证过的酒馆版本、入口、角色字段、关联世界书读取、模型接口、事件和存储方法。每项写明参数、返回值、异常及能力缺失策略。

- 禁止猜测导出函数名、事件名、相对导入路径及接口响应格式。
- 不修改酒馆核心文件，不全局覆盖原生方法，不操作不属于扩展的 DOM。
- 所有事件监听、观察器、计时器和弹窗挂载都必须可清理，重复初始化不得重复注册。
- 自动任务捕获角色、聊天、故事版本及任务 ID；返回时验证目标仍一致。
- 切换角色/聊天取消旧请求或丢弃其过期结果，不写进当前角色。
- 优先复用当前酒馆模型连接；独立连接属于后续显式功能，不擅自读取或持久化密钥。

## 6. 数据契约与状态

- 集中定义并运行时校验 Story、Node、Edge、SourceSnapshot、RunState、GenerationJob。
- 所有持久化及导入导出数据包含 schemaVersion；迁移必须有旧版本样例和失败保留策略。
- 事实来源、原创草稿、采用版本及本局状态分层保存，不复用同一对象承载四种含义。
- 采用前校验图结构、条件、引用和必填信息；非法内容保留为草稿，不混入有效版本。
- ID 在重命名、拖动及局部重生成后保持稳定；删除节点同步处理关联边并可恢复。
- 不默认覆盖手工修订；重生成提供差异并尊重锁定信息。
- 存储操作有明确成功/失败结果；写失败不更新“已保存”状态。采用与对应版本写入作为一致性操作处理。
- 故事设计按角色组织，本局进度按聊天隔离；无法识别聊天时不自动保存进度到通用键。

## 7. AI 调用与输出规则

- 提示模板集中管理，带版本和用途；解析、创作、建议使用不同模板和结果契约。
- 来源文本作为数据隔离，明确不执行其中的命令。不得给解析任务开放执行脚本或任意工具权限。
- 模型结果必须经历解析、结构校验、引用核对、图校验、业务校验，再成为可采用草稿。
- JSON 修复最多自动尝试一次，并记录原因；失败向用户报告，不使用空结果或假数据回退为成功。
- 解析模式没有原文证据就标推断；禁止伪造书名、UID、摘录、时间或固定路线。
- 批次结果包含来源范围和完成状态；截断、超时及取消都不能标整本解析完成。
- 请求支持取消和超时；重复提交防重；网络重试必须有上限且可见，不无限循环消耗额度。
- 生成任务不得自动采用、自动发消息、改原角色卡或写原世界书。
- 无剧透建议仅接收允许展示的资料；不能把全攻略交给模型后仅靠“不要剧透”一句话保护。

## 8. 图与条件

- 图结构由领域层校验；图组件只负责展示与交互。
- 业务数据不依赖图库内部对象；布局坐标与剧情含义分开存储。
- 不用 Mermaid 文本充当可编辑故事数据库。文档可用 Mermaid 示意。
- 首版禁止环路；校验入口、结局可达性、悬空边、重复 ID、孤立节点和不合法条件。
- 条件采用声明式有限操作集合；禁止 eval、new Function 和将自然语言直接转成可执行 JS。
- 变量不存在或类型不匹配时返回“未知/待判断”，不能默认真。
- 所有视图共用可见性计算，隐藏节点不能在连线、计数、搜索和无障碍描述中泄漏。

## 9. 前端质量与安全

- 样式使用扩展根容器和命名前缀，禁止裸全局选择器改酒馆按钮、表单、body 或通用类。
- 弹窗保留关闭操作，关闭后焦点回到入口；键盘导航和窄屏可用。
- 每个异步区域有加载、空、错误、部分完成与成功状态；表单有防重复提交。
- 缺世界书、缺模型、读取失败、响应无效、网络中断、存储满分别处理，提供可执行恢复路径。
- 原文和模型输出默认以纯文本渲染；富文本必须白名单净化；禁止未经处理的 innerHTML/v-html。
- 导入 JSON 设置体积、节点数、深度上限，拒绝脚本字段、非法键及无效引用，具体上限在契约中定义并测试。
- 用户 URL 不成为自动执行或资源下载入口；不从 CDN 动态执行未锁定脚本。
- 删除或替换已有故事需要预览和恢复方式；不为普通阅读增加确认弹窗。

## 10. 测试要求

优先测试可能损坏故事、污染存档或误导玩家的逻辑，不为纯样式变化制造实现镜像测试。

- 日常修改只检查本次功能、直接依赖及其自动化测试，使用明确文件列表运行相关测试，不默认扫描全项目或执行全量检查；全量发布验收另行安排。
- 多个人工或 AI 同时工作时，修改前与交付前核对 Git 状态和目标文件差异；保留他人未提交改动，不执行全仓格式化、重置、清理或覆盖。共享文档仅追加本次必要条目；共用构建产物须说明由当前工作区生成，不能将他人源码改动归为本次成果。

| 范围       | 必测案例                                                 |
| ---------- | -------------------------------------------------------- |
| 图与条件   | 分支汇合、悬空边、环路、不可达结局、未知变量、类型错误   |
| 来源       | 错误 UID、无依据摘录、重复条目、来源改动后失效、推断标识 |
| AI         | 非 JSON、缺字段、截断、部分完成、取消、修复失败          |
| 存档       | 两角色两聊天隔离、迁移失败、配额失败、导入冲突、版本切换 |
| 并发       | 连点生成、切角色后返回、旧请求覆盖新结果                 |
| 剧透与渲染 | 搜索/图/列表一致隐藏、HTML 注入、恶意来源文本            |

发布前必须在真实酒馆完成安装、打开、解析、无书创作、图编辑、采用、刷新恢复、导出导入及卸载检查。Mock 测试不能替代真实宿主兼容性证据。

建立构建工具后必须提供固定的 typecheck、lint、test、build 命令，并在 README 列出实际命令。当前没有工具链，不能声称这些检查已通过。

## 11. 变更与完成标准

开发前阅读 AGENTS、需求、相关契约与现有代码，列出对应 FR 和改动范围。一次完成一个可验收切片，不整仓重写、不夹带无关重构、不删除用户文件。

完成汇报必须包含：改变的行为、关联 FR、实际执行的验证、结果、未覆盖场景与兼容限制。禁止把“写完代码”“编译通过”表述为“真实酒馆全部可用”。

评审要求业务文档、契约、代码、存储迁移、测试保持一致；无数据库时不伪造数据库迁移要求。

审查等级沿用用户提供的 frontend-review 思路：

- **阻断**：数据污染/丢失、密钥泄漏、脚本执行、无法安装、来源造假、越过用户采用流程、核心 P0 不成立。
- **重要**：错误恢复缺失、重复调用、剧透泄漏、兼容性未说明、关键测试缺失。
- **建议**：不影响正确性的文案、布局及可维护性改善。

每条发现提供文件路径、具体行号、触发场景及影响；无法验证的推断必须标明。

## 12. 参考技能的适用范围

已读取用户提供的 `h:/vueAIAdmin/.claude/skills/frontend-review/SKILL.md`。采用其契约对齐、错误分支、安全渲染、中文业务注释、状态反馈和分级审查原则。不照搬 vue-aiadmin 的 `/api/v1`、登录、Token 时限、数据库和后台路由规范。

## 13. Git 提交说明

- 后续人工与 AI 编写的提交标题、正文均使用中文说明改动；代码标识符、文件名、命令和技术专名可保留原文。
- 标题格式为 `类型: 中文说明`；需要限定模块时使用 `类型(范围): 中文说明`。
- 类型保留常用英文前缀：`feat` 新功能、`fix` 修复、`docs` 文档、`refactor` 重构、`test` 测试、`style` 格式、`build` 构建、`ci` 持续集成、`chore` 维护、`revert` 回退。
- 标题简明说明具体改动，避免“更新一下”“修改代码”等无法识别内容的表述；一次提交围绕一个明确目的。
- 复杂变更在正文补充原因、影响、关联 FR 编号和实际验证结果；文档或工具链变更可注明不涉及功能 FR，不编造验收结果。
- 此规范约束后续新提交，不为统一语言重写已发布历史；Git 自动生成的合并、回退等说明可保留，手写补充说明使用中文。

示例：

```text
feat(素材库): 添加分类搜索与收藏功能
fix(存档): 修复切换角色后旧结果覆盖当前数据
docs: 补充中文 Git 提交说明规范
test(素材库): 覆盖来源校验与角色隔离
```

## 14. 更新日志与版本文档

- 仓库根目录 `CHANGELOG.md` 面向玩家记录每个已发布版本的日期、新增、调整、修复及升级注意事项，最新版本置顶；未发布计划单独标记，禁止混入已实现内容。
- `VERSION.md` 记录当前扩展版本、已验证宿主范围、数据格式、更新方法及版本历史；不能把已测试版本写成未经确认的最低兼容版本。
- 功能发布同步修改 manifest、package、锁文件根项目版本、README、更新日志、版本说明及验证记录；构建产物随源码提交。纯文档维护无需增加扩展版本号。
- 版本日期、功能范围和测试声明以实际提交与验证记录为依据，Mock 与真实宿主分开报告，不虚构 GitHub Release、标签或模型测试状态。

# Galgame 路线与草稿后续实施计划

日期：2026-11-14。用户授权先发布0.7.0，再继续补齐剩余功能，按实际体验逐项调整。0.7.0发布提交a5a933d；后续改动使用codex/galgame-p1。

**Goal:** 完成人物路线管理、核心场景拆分合并以及可审阅采用的AI候选关系/路线草稿。

**Spec:** ../../galgame-product-plan.md；FR-02/03/05/08/09/10。

## 剩余功能盘点

- 当前已有：资料/事件分离、共享事件、手动连接持久化、正式阅读、移动端、保守重导入及恢复、多消息核心场景提取。
- 本轮补齐：路线重命名/人物与类型管理/删除不删共享事件；场景拆分合并及原证据保护；AI推断/扩展/混合草稿的生成、编辑、逐项确认/拒绝、保存恢复与采用。
- 后续：完整工坊体验优化、聊天转本局事件、自动进度/解锁、分享；真实模型提取质量与大图性能继续独立验证。

## 分工与接口

- [x] AI领域与应用：新增独立route-drafts领域及生成用例，复用宿主requestModel；不直接写正式路线，采用时检查基线与依赖；测试错误引用、越权新增、取消、过期、采用冲突及部分确认。
- [x] 草稿UI：独立workshop视图，目标人物/来源/风格/长度/模式，生成预览与编辑、确认拒绝及采用；移动表单可用，窗口生命周期守卫；只在workspace增加一个入口，避免与主代理重构冲突。
- [x] 素材操作：补保存后拆分/合并，证据只复用原快照，不添加原文；事务保留原记录及恢复，JSON备份导入预览避免覆盖；兼容旧素材。
- [x] 主代理：路线管理领域/UI、文档契约、集成验证、独立审查与真实宿主验证；完成后提交可审阅下一版本。

## 执行约束

不新增后台/云服务，不自动发消息或改原世界书。世界书与模型输出只当数据；新模型请求由用户主动触发。不新增真实模型自动调用测试；Mock与真实宿主明确分开。旧库缺新可选字段仍可读；新草稿能力先设计版本与备份，不原地覆盖旧内容。

每个高风险切片先写失败测试再实现，针对检查后统一类型/lint/单测/构建/浏览器验收。0.7.0远端发布不因本地下一版本开发自动改变。


## 本轮验收与后续

已完成上述基础切片，验收记录见 ../../verification.md。AI 草稿含多结局结构校验与采用，未确认内容不进入正式图；候选预览为简图，完整交互继续迭代。

下一轮优先按实际反馈调整世界书分类与关键事件提取质量；其后接入聊天到本局事件候选、人工确认进度及解锁。分享、复杂布局和大图性能保持后续项，不自动扩展为后台服务。
